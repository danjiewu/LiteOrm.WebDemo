Feather-light, lightning-fast

LiteOrm is a lightweight, high-performance .NET ORM framework—the execution speed of a micro ORM with the ergonomics of a full ORM. Built for workloads that are performance sensitive but still need to handle complex SQL.

Features

Why LiteOrm

The execution speed of a micro ORM with the ergonomics of a full ORM—without hiding SQL, and without forcing you to hand-write it.

Blazing fast

Performance close to raw Dapper and far ahead of EF Core. Bulk insert, update and association queries all lead the field, with the smallest allocation footprint.

Three query styles

Lambda, Expr and ExprString mix freely: strongly typed filters, dynamically built conditions, and hand-written SQL fragments at the DAO layer—each used where it fits.

Automatic associations

Declare relations with [ForeignType] / [TableJoin]—no hand-written JOINs—and filter by a related table in one call with ExistsRelated.

Declarative transactions

The [Transaction] attribute brings AOP transaction management with nesting and rollback, leaving business code untouched.

11 database dialects

SQL Server, MySQL, Oracle, PostgreSQL and SQLite, plus built-in support for the domestic databases DM, KingbaseES, GaussDB, OceanBase, TiDB and GreatDB.

Sharding and read/write splitting

The IArged interface routes sharded tables, while multiple data sources and read-only replicas work out of the box—covering the everyday needs of mid-size and large systems.

Query

One query, three ways

All three produce parameterized SQL. Lambda reads best, Expr suits dynamic composition, and ExprString is there for the DAO layer when you need precise control over the SQL.

// Write queries the way you write C#: strongly typed, highly readable
var users = await userService.SearchAsync(
    u => u.Age >= 18 && u.UserName!.StartsWith("A"));

// Sorting + paging
var page = await userService.SearchAsync(
    q => q.Where(u => u.Age >= 18)
          .OrderByDescending(u => u.CreateTime)
          .Skip(20).Take(10));
// Compose conditions dynamically: ideal for query builders and admin filters
using static LiteOrm.Common.Expr;

var expr = (Prop("Age") >= 18)
          & Prop("UserName").StartsWith("A");
var users = await userService.SearchAsync(expr);

// Conditions serialize to JSON, so they travel across layers or come straight from the client
string json = expr.ToJson();
// Interpolated strings for hand-written SQL fragments, DAO layer only
using static LiteOrm.Common.Expr;

int minAge = 18;
var users = await userViewDAO.Search(
    $"WHERE {Prop("Age")} > {minAge}")
    .ToListAsync();

// Interpolated values are parameterized automatically: flexible and safe

The service layer exposes Lambda / Expr entry points plus SearchAs projection queries; the DAO layer additionally opens up ExprString, DataTable queries and other low-level capabilities. See the query overview.
